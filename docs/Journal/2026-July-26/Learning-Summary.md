# Module Covered

## Module 3 – Database Design (Started)

Today's learning marked the beginning of Module 3 by shifting from software architecture to database thinking.

Instead of starting with tables, columns, or SQL, the focus was on understanding how a database represents the real business.

The SKCP factory became the primary learning model for every database concept.

---

# Major Concepts Learned

## 1. What is a Database?

A database is an organized collection of information about a business.

Instead of storing random data, a database stores information about real-world business objects and the relationships between them.

For SKCP, the database will represent the daily operations of the cement block factory.

---

## 2. Business Objects Become Database Entities

Every important object inside the business eventually becomes a database entity.

Examples include:

- Customer
- Supplier
- Product
- Inventory
- Order
- Payment
- Production Batch
- Labour
- Machine

This established the connection between business analysis and database design.

---

## 3. Entity Thinking

Rather than asking,

"What tables should I create?"

the better question is,

"What things actually exist inside the business?"

This business-first mindset simplifies database design and produces more accurate systems.

---

## 4. SKCP Learning Bridge™

A new learning approach was introduced.

Every business question is translated into its database equivalent.

Examples:

Business Question → Database Concept

Customer → Customer Table

Order → Orders Table

Payment → Payments Table

Inventory → Inventory Table

Production → Production Table

This bridge makes abstract database concepts easier to understand by connecting them to daily factory operations.

---

## 5. Attributes

An entity is described by its attributes.

Example:

Customer

Attributes include:

- Customer Name
- Phone Number
- Address
- WhatsApp Number
- Pending Amount

Attributes provide detailed information about each business object.

---

## 6. Unique Identification

Every business object requires a unique identifier.

Examples include:

- Customer ID
- Product ID
- Supplier ID
- Order ID
- Payment ID
- Inventory ID

Unique IDs prevent ambiguity and allow records to be linked accurately.
